# 管理员使用记录：24 小时输入 / 输出详情

## 使用方式

- 管理员 → **使用记录** → 每条记录的「输入 / 输出」列 → **查看对话**。
- 「错误请求」页的操作列也有「查看对话」，可查看鉴权成功后产生的未计费错误请求。
- 默认显示可读对话：系统提示、历史消息、当前输入、返回的文本 / 思考内容与工具调用；可切换「原始 JSON / SSE」查看实际请求和响应正文。
- SSE 流式响应按发送顺序保存；OpenAI Responses WebSocket 按轮次单独记录，计费任务固定引用自己的轮次，不会串到下一轮。
- 只保存功能上线后的请求。历史请求无法补录，鉴权前拒绝的请求不抓取，二进制图片 / 音频 / 视频 / multipart 正文不保存。JSON 内嵌媒体仍属于受大小限制的原文。

## 保留与权限

- 保留期固定为采集开始后 **24 小时**，不能通过配置延长。所有正文查询都检查到期时间，页面打开的正文也会在到期或关闭时清空。
- 启动时和每分钟自动清理，每批最多 1,000 行；一次清理最多 10 批、3 秒。异常积压可能延迟物理删除，但过期正文始终不可通过详情接口读取。
- 原有 `usage_logs`、费用、交易和统计不受正文清理影响。
- 正文不加入使用记录列表 DTO、Excel 导出、仪表盘缓存或浏览器持久化存储。只有完整管理员可访问详情接口，普通用户、观察员、受限管理密钥均不能读取。
- 响应使用 `Cache-Control: no-store` 和 `nosniff`，敏感读取进入管理员操作审计；审计中只记录操作与 ID，不复制对话正文。原文作为文本展示，不执行用户 HTML、不加载媒体 URL。
- 采集器不保存 Authorization、Cookie、API Key 等请求头，也不保存带密钥的查询参数。不过用户在对话正文中自行输入的敏感信息仍会被记录；运营方应明确告知用户并遵守隐私及数据处理要求。
- 程序自带 `pg_dump` 备份排除 `usage_request_contents` 的数据，恢复后会校正容量计数。外部数据库备份、WAL、磁盘快照和管理员手工复制不属于安全擦除范围；不要把临时正文另行归档。已有的手动诊断抓取任务仍沿用其独立的配置。

## 性能保护

- 独立 PostgreSQL 表 `usage_request_contents`，普通用量查询不连接或读取正文。
- 请求链路仅有有界复制和非阻塞入队；**不等待 gzip、磁盘或 SQL**，不更改转发内容、SSE flush、模型调度与计费流程。
- 固定 1 个后台写入 worker，最多 16 个请求一批；gzip 使用 `BestSpeed` 并复用编码器。SQL 写入最多 2 秒，短重试最多 3 次，没有每个请求新增 goroutine 或同步兜底。
- 默认每个方向最多保存 **2 MiB**，最多 512 个采集会话，正文缓冲合计 **64 MiB**、队列 256 项；另有少量有界压缩和管理端解码空间。超过限制只丢弃 / 截断诊断内容，页面明确提示，聊天与计费照常运行。
- 临时存储默认 **1 GiB 的正文、元数据和索引开销估算预算**。后台批次用一个短事务更新容量计数；多实例共享同一预算，不对每条请求反复做 `SUM` 或全表扫描。达限暂停采集，过期清理释放容量后恢复。预算不是数据库物理文件大小的硬上限；PostgreSQL VACUUM 复用空间，文件、索引及 WAL 有额外开销。
- 管理端点击才加载一个正文，同时最多 2 个解码读取者；其他实际重试仅返回最多 20 个小型索引引用。
- 到期索引 + 小批删除 + 更积极的普通 / TOAST autovacuum，避免给永久计费表加大字段或进行大事务清理。

### 配置（重启应用生效）

```yaml
gateway:
  usage_content:
    enabled: true
    max_body_bytes: 2097152
    max_storage_mib: 1024
```

对应环境变量：

- `GATEWAY_USAGE_CONTENT_ENABLED`：默认 `true`；关闭后停止新增记录，但仍清理并允许管理员查看未过期历史。
- `GATEWAY_USAGE_CONTENT_MAX_BODY_BYTES`：默认 `2097152`，0 使用默认值，上限 `8388608`。
- `GATEWAY_USAGE_CONTENT_MAX_STORAGE_MIB`：默认 `1024`，0 使用默认值，上限 `102400`。

## 验证覆盖

- 原始 / gzip / preread 输入、普通 JSON、SSE、直接 JSON binding，转发原文不被截断。
- 后台计费在 HTTP 完成后绑定、重复绑定、被丢弃的计费任务、不同用户 / API Key 隔离。
- WebSocket 首轮原文、不同轮次隔离、下一轮先于上一轮计费回调到达的竞态。
- 内存 / 队列 / 单正文 / 存储预算保护，预算释放后恢复、gzip 解压上限、重启和关闭时清理。
- 管理员权限、无缓存响应、历史 / 过期提示、只在点击时查询、关闭 / 切换时取消旧查询、页面到期清空、文本安全展示。
- 本地热链路基准（20 KiB 输入输出合计，Windows / Ryzen 7 7840H）：约 **7–10 微秒 / 请求**、33,512 B 分配；该基准仅衡量采集复制与入队，不代表生产端到端耗时或所有负载下的性能保证。

后台状态计数通过管理员正文详情响应的 `stats` 返回，包括缓冲、队列、保存、丢弃、截断、写入 / 清理失败和存储达限。过载、重启瞬间或存储故障时正文可能缺失；不可为了保证诊断记录而阻塞或重复发起计费 / 模型请求。
